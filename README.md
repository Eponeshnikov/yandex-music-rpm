# yandex-music-rpm

Яндекс Музыка для Linux официально выходит только в `.deb`. Этот набор скриптов
ставит её на RPM-дистрибутивы (Fedora, RHEL, openSUSE и т.п.): качает актуальный
`.deb`, пересобирает его в RPM через `alien`, ставит через `dnf` — и **чинит
кнопку «Обновить» внутри самого приложения**.

## Зачем патч

Приложение собрано на Electron и обновляется через `electron-updater`. Его
`DebUpdater` жёстко зашивает команду установки:

```js
const cmd = ["dpkg", "-i", installerPath, "||", "apt-get", "install", "-f", "-y"];
```

На RPM-системе ни `apt-get`, ни базы `dpkg` нет, поэтому кнопка «Обновить»
показывает polkit-запрос пароля и после него молча ничего не делает.

`patch-yandex-music-updater` заменяет этот массив прямо в
`resources/app.asar` — **байт в байт той же длины**, поэтому заголовок asar
с офсетами остаётся валидным и распаковка/переупаковка не нужна:

```js
const cmd = ["/usr/local/bin/yandex-music-install", installerPath]               ;
```

Дальше приложение само вызывает `pkexec /bin/bash -c '…'`, а хелпер уже делает
`alien` + `dnf install` и заново накладывает патч на свежий `app.asar`.

## Откуда берётся версия

Два разных источника у Яндекса:

| Источник | Что это |
|---|---|
| `stable/download.json` | кнопка «Скачать» на сайте — только полностью раскатанные сборки |
| `stable/latest-linux.yml` | фид `electron-updater`, из него баннер «Доступна версия X» в приложении |

`yandex-music-update` по умолчанию читает **`latest-linux.yml`**, поэтому не
отстаёт от баннера в приложении (у сборок там есть `updateProbability` —
поэтапная раскатка), и проверяет `sha512` скачанного пакета из того же фида.
Флаг `--download-json` возвращает старое поведение.

## Установка

```bash
git clone https://github.com/Eponeshnikov/yandex-music-rpm.git
cd yandex-music-rpm
./install.sh
```

Установщик:

* проверит зависимости и доставит `alien`, если его нет;
* положит три скрипта в `/usr/local/bin`;
* пропатчит уже установленную Яндекс Музыку;
* добавит алиас `ymupd` в `~/.bashrc`.

Один запрос пароля на всё (через `sudo`, а без терминала — через `pkexec`).

Опции: `--alias NAME`, `--no-alias`, `--no-patch`, `--no-deps`, `--prefix DIR`.

## Использование

```bash
ymupd                  # обновить (или поставить с нуля)
ymupd --check          # только показать версии; код возврата 1 = есть обновление
ymupd --force          # переустановить текущую версию
ymupd --download-json  # взять версию с сайта, а не из фида приложения
```

Кнопка «Обновить» в приложении после патча работает сама — она вызывает
`yandex-music-install`, который конвертирует `.deb` и ставит его через `dnf`.
Лог: `/var/log/yandex-music-install.log`.

## Состав

| Файл | Что делает |
|---|---|
| `bin/yandex-music-update` | CLI: версия из фида → скачивание → проверка `sha512` → установка |
| `bin/yandex-music-install` | root-хелпер: `alien` → `dnf install` → перепатч `app.asar` |
| `bin/patch-yandex-music-updater` | правка команды обновления в `app.asar` (`--check`, `--revert`) |
| `install.sh` / `uninstall.sh` | установка и полный откат |

## Удаление

```bash
./uninstall.sh          # откатить патч, убрать скрипты и алиас
sudo dnf remove yandexmusic
```

## Требования

`curl`, `python3`, `rpm`, `dnf`, `alien` (ставится автоматически), `sudo` или `pkexec`.

## Заметки

* Патч живёт в `app.asar` и слетает при каждой переустановке пакета — оба пути
  установки накладывают его заново автоматически.
* Если Яндекс изменит команду в `electron-updater`, патчер честно скажет
  `install command not found` и ничего не тронет.
* Проект не связан с Яндексом; распространяется как есть.
