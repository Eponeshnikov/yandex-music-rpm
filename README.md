# yandex-music-rpm

Яндекс Музыка для Linux официально выходит только в `.deb`. Этот набор скриптов
ставит её на RPM-дистрибутивы: качает актуальный `.deb`, пересобирает в RPM,
ставит родным пакетным менеджером — и **чинит кнопку «Обновить» внутри самого
приложения**.

## Дистрибутивы

Пакетный менеджер определяется по `/etc/os-release`, дистрибутивный имеет
приоритет над «универсальным»:

| Дистрибутив | Менеджер | Как ставится `.deb` |
|---|---|---|
| Fedora, RHEL, CentOS, Alma, Rocky | `dnf` | `alien -r` → `dnf install --allow-downgrade` |
| openSUSE, SLE | `zypper` | `alien -r` → `zypper install --oldpackage` |
| ALT Linux (с eepm) | `epm` | `epm --repack install` — репак у eepm свой, `alien` не нужен |
| ALT Linux (без eepm) | `apt-get` + `rpm` | `alien -r` → `rpm -Uvh --oldpackage` |

Переопределить автоопределение: `YM_PM=epm ./install.sh`.

Всё, что зависит от менеджера, вынесено в `lib/ym-common.sh`; остальное
(патч `app.asar`, фоновый воркер, работа с фидом) от дистрибутива не зависит.
Проверено вживую на Fedora 44; ветки ALT и openSUSE прогонялись на
подставленном окружении, не на живых системах.

## Зачем патч

Приложение собрано на Electron и обновляется через `electron-updater`. Его
`DebUpdater` жёстко зашивает команду установки:

```js
const cmd = ["dpkg", "-i", installerPath, "||", "apt-get", "install", "-f", "-y"];
```

На RPM-системе ни `apt-get`, ни базы `dpkg` нет, поэтому кнопка «Обновить»
показывает polkit-запрос пароля и после него молча ничего не делает.

`patch-yandex-music-updater` правит `resources/app.asar` **байт в байт той же
длины**, поэтому заголовок asar с офсетами остаётся валидным и
распаковка/переупаковка не нужна. Патчей два:

```js
// install-command
const cmd = ["/usr/local/bin/yandex-music-install", installerPath]               ;

// no-relaunch: свойства isForceRunNever не существует, значит relaunch не будет
if (options.isForceRunNever) {
    this.app.relaunch();
}
```

Первый переводит установку на хелпер: приложение вызывает
`pkexec /bin/bash -c '…'`, а тот делает `alien` + `dnf install` и заново
накладывает патчи на свежий `app.asar`.

Второй убирает `app.relaunch()` из `DebUpdater.doInstall`. Без него приложение
успевает вернуться на **старой** версии прямо посреди установки, снова показать
баннер «Доступна версия…» и зависнуть, когда установщик его останавливает.
С патчем оно просто закрывается, а новую версию запускает уже хелпер.

### Почему хелпер уходит в фон

`electron-updater` запускает команду установки через **синхронный** `spawnSync`,
поэтому пока идёт конвертация, интерфейс приложения полностью висит — рабочий
стол успевает предложить «Force Quit», и установка обрывается на середине.

Поэтому по умолчанию `yandex-music-install` отвечает мгновенно (~1 с), а работу
доделывает фоновый воркер:

1. определяет пользователя (`PKEXEC_UID`, иначе владелец процесса приложения,
   иначе владелец скачанного `.deb`) и его шину `/run/user/$UID/bus`;
2. ждёт 5 с, пока приложение закроется само, и на всякий случай гасит остатки —
   `SIGTERM`, через 8 с `SIGKILL`, на `SIGTERM` приложение не реагирует;
3. конвертирует и ставит пакет, перепатчивает `app.asar`, удаляет скачанный
   `.deb` из `~/.cache/yandexmusic-updater/pending/`;
4. запускает приложение обратно — через `systemd-run --user`, чтобы оно не
   умерло вместе с воркером, — и шлёт уведомление.

Сам воркер живёт в transient-юните systemd (`systemd-run`), то есть вне cgroup
приложения: даже «Force Quit» посреди установки её не прервёт. Юнит стартует с
чистым окружением, поэтому uid пользователя передаётся в него явно — иначе не
будет ни уведомлений, ни автозапуска.

Установки сериализованы через `flock`: два клика по «Обновить» не наложатся друг
на друга — второй дождётся первого и выйдет, увидев, что версия уже стоит.

Конвертация ускорена макросом `%_binary_payload w0.gzdio` (RPM без сжатия —
он всё равно одноразовый): ~90 МБ пакет конвертируется за 8 с вместо ~105 с.
От нажатия кнопки до перезапущенного приложения — около 30 с.

## Откуда берётся версия

Два разных источника у Яндекса:

| Источник | Что это |
|---|---|
| `stable/download.json` | кнопка «Скачать» на сайте — только полностью раскатанные сборки |
| `stable/latest-linux.yml` | фид `electron-updater`, из него баннер «Доступна версия X» в приложении |

Первая установка идёт с `download.json` (то же, что кнопка «Скачать» на сайте),
дальше обновления приходят из фида приложения.

`yandex-music-update` по умолчанию читает **`latest-linux.yml`**, поэтому не
отстаёт от баннера в приложении (у сборок там есть `updateProbability` —
поэтапная раскатка), и проверяет `sha512` скачанного пакета из того же фида.
Флаг `--download-json` возвращает старое поведение.

## Установка

```bash
git clone https://github.com/Eponeshnikov/yandex-music-rpm.git
cd yandex-music-rpm
./install.sh
```

Установщик:

* проверит зависимости и доставит `rpm-build` и конвертер (`alien` или `eepm`),
  если их нет;
* положит три скрипта в `/usr/local/bin`;
* **если Яндекс Музыка не установлена — скачает и поставит её** (версия с
  `stable/download.json`, как с сайта), если установлена — просто пропатчит;
* добавит алиас `ymupd` в `~/.bashrc`.

Один запрос пароля на всё (через `sudo`, а без терминала — через `pkexec`).
Чистая установка с нуля занимает около 25 секунд.

Опции: `--alias NAME`, `--no-alias`, `--no-patch`, `--no-app`, `--no-deps`,
`--prefix DIR`.

## Использование

```bash
ymupd                  # обновить (или поставить с нуля)
ymupd --check          # только показать версии; код возврата 1 = есть обновление
ymupd --force          # переустановить текущую версию
ymupd --download-json  # взять версию с сайта, а не из фида приложения
```

Кнопка «Обновить» в приложении после патча работает сама — она вызывает
`yandex-music-install`, который конвертирует `.deb` и ставит его через `dnf`.
Лог: `/var/log/yandex-music-install.log`.

## Состав

| Файл | Что делает |
|---|---|
| `bin/yandex-music-update` | CLI: версия из фида → скачивание → проверка `sha512` → установка |
| `bin/yandex-music-install` | root-хелпер: конвертация → установка → перепатч `app.asar`; по умолчанию фоново, `--foreground` — синхронно |
| `lib/ym-common.sh` | определение пакетного менеджера, установка/удаление пакетов, проверка зависимостей |
| `bin/patch-yandex-music-updater` | правка `app.asar`: команда установки и отмена самоперезапуска (`--check`, `--revert`) |
| `install.sh` / `uninstall.sh` | установка и полный откат |

## Удаление

```bash
./uninstall.sh              # остановить приложение, снести пакет, скрипты и алиас
./uninstall.sh --keep-app   # оставить приложение, только откатить патч и убрать скрипты
```

## Требования

`install.sh` проверяет всё сам: обязательное доставляет через найденный
пакетный менеджер, про необязательное пишет, что именно отвалится и какой
командой это поставить.

**Обязательно:** `curl`, `rpm`, `python3`, `rpmbuild` (пакет `rpm-build`),
пакетный менеджер из таблицы выше и конвертер — `epm` (ALT) или `alien`
(везде). `rpmbuild` нужен обоим конвертерам: `alien` зовёт его напрямую, репак
у eepm — тоже. Без него конвертация падает уже в процессе установки.

**Необязательно, но лучше иметь:**

| Утилита | Пакет | Без неё |
|---|---|---|
| `openssl` | `openssl` | не проверяется `sha512` из фида |
| `pkexec` | `polkit` | кнопке «Обновить» негде спросить пароль |
| `systemd-run` | `systemd` | фоновая установка откатывается на `setsid` |
| `notify-send` | `libnotify` (`libnotify-tools` в openSUSE) | нет уведомлений об обновлении |
| `flock` | `util-linux` | два клика по «Обновить» не сериализуются |

Проверить руками: `yandex-music-update --check` откажется работать со списком
недостающего и готовой командой установки.

## Заметки

* Патч живёт в `app.asar` и слетает при каждой переустановке пакета — оба пути
  установки накладывают его заново автоматически.
* Ход установки из приложения виден в `/var/log/yandex-music-install.log` и в
  журнале: `journalctl -u 'yandex-music-install-*'`.
* Если Яндекс изменит команду в `electron-updater`, патчер честно скажет
  `install command not found` и ничего не тронет.
* Проект не связан с Яндексом; распространяется как есть.
* Имя пакета можно переопределить через `YM_PACKAGE`, пакетный менеджер — через
  `YM_PM`, путь к библиотеке — через `YM_LIB`.
